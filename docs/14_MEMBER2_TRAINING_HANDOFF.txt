M04：可选 gradient_accumulation_steps，默认 1，现有配置行为保持不变。
最后不足一组的 microbatch 仍更新；按实际样本数加权，clip/scheduler 仅在更新时执行。
每 epoch optimizer steps = ceil(min(ceil(N/microbatch), max_steps或无限)/accumulation)。
有效 batch = microbatch * accumulation（最后不足一组除外）。
注意 BatchNorm、Dropout 和按 batch 平衡的边界损失意味着累计并不等价于大物理 batch。
如果采用累计，A/B/C/D 应统一 microbatch、累计次数、数据、epoch 和精度；不可只改一组。

每组最多 20 个 microbatch，并评估全部 validation；资源表在 resources.json。
步时经过 CUDA 同步，steady_microbatch_seconds 丢弃前两步，不含 DataLoader 等待；

OOM 明确记为失败；A 的显存测量不代表 B/D，可用其各自配置补测。

运行（项目根目录；python 应指向安装了 requirements.txt 的环境）
  python scripts/member2_pilot.py --output runs/member2_real_pilot
  python -m transparent_seg.train --config configs/member2_overfit.json --output runs/member2_overfit
  python -m transparent_seg.train --config <冻结配置.json> --output runs/A_part --stop-after-epoch 5
  python -m transparent_seg.train --config <同一冻结配置.json> --output runs/A_resume --resume runs/A_part/last.pt
新 run 的 history.jsonl 只含恢复后的 epoch；resume.json 记录源 checkpoint 路径/哈希，
查看完整曲线需按 epoch 拼接父 run 和恢复 run 的 history，不重复计入恢复点之前的数据。
epoch 的 seconds 包含存盘；资源估算请使用独立 train_seconds/validation_seconds。

精确 GPU 复现
配置加入 "deterministic": true，并在启动 Python 前设置：
  $env:CUBLAS_WORKSPACE_CONFIG=':4096:8'
此选项对全部消融一致使用。默认仍为原协议的非严格确定性模式，可能有微小 CUDA 差异。
同硬件/软件的验证不保证跨 GPU 或跨依赖版本逐位一致。
